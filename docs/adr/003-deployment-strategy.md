# ADR 003: 배포 전략

- **상태**: 채택 (Accepted)
- **날짜**: 2025-11-10

## Context (맥락)

- **문제**: 서비스를 운영하는 중에 새로운 버전의 어플리케이션을 배포해야 합니다. 기존의 단순한 덮어쓰기 방식(In-place update)은 배포 과정에서 수 초에서 수 분간의 서비스 중단을 유발하며, 배포 실패 시 롤백(Rollback) 과정이 복잡하고 시간이 오래 걸립니다.
- **요구사항**: 사용자가 서비스를 이용하는 데 불편함이 없도록 서비스 중단 없이(Zero-downtime) 배포가 이루어져야 합니다. 또한, 배포된 버전에 문제가 발견될 경우 빠르고 안전하게 이전 버전으로 되돌아갈 수 있어야 합니다.

## Decision (결정)

- **Blue/Green 배포 전략을 채택**합니다.
- **프로세스**:
  1. 현재 운영 중인 환경(Blue)과 동일한 구성의 신규 환경(Green)을 준비합니다.
  2. Green 환경에 새로운 버전의 어플리케이션을 배포하고, 내부적으로 테스트를 진행합니다.
  3. 테스트가 완료되면 Load Balancer를 통해 모든 실시간 트래픽을 Blue에서 Green으로 일제히 전환합니다.
  4. Green 환경이 정상적으로 트래픽을 처리하는 것을 확인한 후, 이전 버전인 Blue 환경은 대기 상태로 두거나 제거합니다.

## Consequences (결과)

### 긍정적 측면
- **무중단 배포**: 트래픽 전환 시점을 제외하면 사용자는 서비스 중단을 전혀 체감할 수 없습니다.
- **안정적인 롤백**: Green 환경에서 문제가 발생하면, Load Balancer의 라우팅 대상을 다시 Blue 환경으로 변경하는 것만으로 즉시 롤백이 가능합니다.
- **충분한 테스트 시간**: 신규 버전에 트래픽을 보내기 전에 Green 환경에서 충분한 시간 동안 안정성 및 기능 테스트를 수행할 수 있습니다.

### 부정적 측면
- **비용**: 운영 환경과 동일한 규모의 환경을 추가로 유지해야 하므로 두 배의 인프라 비용이 발생할 수 있습니다. (배포 기간 동안 일시적으로)
- **데이터베이스 호환성**: Blue 환경과 Green 환경이 동일한 데이터베이스를 공유할 경우, 두 버전 모두와 호환되도록 스키마를 관리해야 하는 복잡성이 있습니다. (Schema backward/forward compatibility)
- **세션 관리**: 상태를 가지는(Stateful) 어플리케이션의 경우, Blue/Green 전환 시 사용자 세션을 유지하기 위한 추가적인 전략이 필요합니다.
